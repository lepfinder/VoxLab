# F6: 实战部署与社区实测

## Findings

### [1] mlx-audio (Blaizzy) is the de-facto MLX hub for VoxLab's TTS/STT/VAD stack: Kokoro, Qwen3-TTS/ASR, VoxCPM2, Silero VAD, Whisper all have first-class ports with mlx-community quantized weights (bf16/8bit/6bit/4bit).
- quote: "The best audio processing library built on Apple's MLX framework, providing fast and efficient text-to-speech (TTS), speech-to-text (STT), speech-to-speech (STS), music generation, and more on Apple Silicon."
- url: https://github.com/lucasnewman/mlx-audio
- source_type: primary
- published: 2026-09 (README as fetched)
- confidence: high

### [2] VoxCPM2 on Apple Silicon is not real-time for production TTS: the official llama.cpp-omni path reports RTF ~1.76 on M4 Pro/Metal (Q8_0), i.e. slower than wall-clock; GPU numbers (RTF 0.30/0.13 on RTX 4090) do not transfer.
- quote: "RTF ~1.76 (Q8_0) on Apple M4 Pro / Metal."
- url: https://github.com/OpenBMB/VoxCPM
- source_type: primary
- published: 2026-04 (VoxCPM2 release) / README as fetched 2026-09
- confidence: high

### [3] Community reports VoxCPM2 long-form Chinese TTS degrades after ~300 characters / ~20s; user claims VoxCPM 1.5 is less affected, across official PyTorch, nano-vLLM, and vLLM-Omni paths.
- quote: "差不多300字左右就开始出现严重问题…20s左右就失真严重了…是不是voxcpm2模型存在问题，1.5好像这个问题没有这么严重"
- url: https://github.com/OpenBMB/VoxCPM/issues/372
- source_type: community
- published: 2026-08-06
- confidence: medium

### [4] VoxCPM2 has an open, reproducible "crackle/spikes" audio artifact report (lifeiteng, with scripts + zips), still open as of Sep 2026.
- quote: "有不小的概率会出现下面这种现象，听起来就是会出现 噼里啪啦的声音"
- url: https://github.com/OpenBMB/VoxCPM/issues/385
- source_type: community
- published: 2026-08-20
- confidence: medium

### [5] Qwen3-TTS ICL voice cloning randomly collapses into ~24s garbage (no EOS, single-token attractor). Root cause is NOT an MLX port bug: official PyTorch A/B shows 3/3 degenerate with truncated ref_text; fix is full ref_text transcription (5/5 clean on MLX).
- quote: "it is not a port bug — it is misaligned ICL prefill caused by ref_text not covering the full reference audio… Official PyTorch, ICL ×3 truncated → 3/3 degenerate 23.92s; MLX stock code, full STT transcription → 5/5 normal"
- url: https://github.com/Blaizzy/mlx-audio/issues/921
- source_type: community
- published: 2026-08-28
- confidence: high

### [6] mlx-audio Qwen3-ASR streaming timestamps are fake: they scale token_count/remaining_tokens by audio_duration, so changing max_tokens changes timestamps for the same audio; one 8.57s test produced 31 events packed into ~0.03s.
- quote: "Qwen3-ASR calculates partial streaming timestamps from token-budget progress: token_count / remaining_tokens * audio_duration… In one 8.57-second test, 31 partial events covered only about the first 0.03 seconds"
- url: https://github.com/Blaizzy/mlx-audio/issues/927
- source_type: community
- published: 2026-08-29
- confidence: high

### [7] mlx-audio Qwen3-ASR had a silent batch bug: list input ignored all but the first audio (closed 2026-08-31). Other open issues: invalid/short/no-speech mishandling (#928) and Whisper non_speech_tokens IndexError (#917).
- quote: "Qwen3-ASR list input silently ignores all but the first audio"
- url: https://github.com/Blaizzy/mlx-audio/issues/926
- source_type: community
- published: 2026-08-31 (closed)
- confidence: high

### [8] Qwen3-ASR official stack is CUDA/vLLM-first: streaming inference is only available with the vLLM backend, not transformers; native Transformers support arrived 2026-06-26. On MLX the community path is mlx-community/Qwen3-ASR-0.6B-8bit and 1.7B-8bit via mlx-audio, not the official package.
- quote: "Currently, streaming inference is only available with the vLLM backend. Note that streaming inference does not support batch inference or returning timestamps."
- url: https://github.com/QwenLM/Qwen3-ASR
- source_type: primary
- published: 2026-01-29 (release) / 2026-06-26 (HF transformers)
- confidence: high

### [9] Qwen3-ASR Chinese/dialect WER is a genuine upgrade over Whisper-large-v3 on paper: WenetSpeech net 4.97 vs 9.86, KeSpeech dialect 5.10 vs 28.79, Dialog-Cantonese 4.12 vs 31.04; but Sichuan (WenetSpeech-Chuan hard) still trails Doubao-ASR (21.63 vs 20.20).
- quote: "WenetSpeech net | meeting: Whisper-large-v3 9.86 | 19.11 vs Qwen3-ASR-1.7B 4.97 | 5.88; KeSpeech 28.79 vs 5.10"
- url: https://github.com/QwenLM/Qwen3-ASR
- source_type: primary
- published: 2026-01-29
- confidence: high

### [10] SenseVoiceSmall has no first-class MLX port; production paths are FunASR (PyTorch), ONNX, Libtorch, and a new llama.cpp/GGUF runtime. Long audio must be VAD-segmented or windowed (30s / 2s overlap) — whole-file encoding OOMs.
- quote: "Passing an hour-long waveform to one model.generate call can make encoder memory grow far beyond the audio file size. When VAD is not acceptable, use the bounded-memory reference script… fixed 30-second windows with 2 seconds of overlap"
- url: https://github.com/QwenAudio/SenseVoice
- source_type: primary
- published: 2026 (README as fetched)
- confidence: high

### [11] SenseVoiceSmall commercial-use license is clarified: MIT for code; official weights under FunASR Model License allow commercial use, Section 3 is a disclaimer not NC restriction; fine-tuned derivatives may stay private. Diarization is NOT in the checkpoint — it's FSMN-VAD + CAM++ composed in FunASR.
- quote: "Commercial use of the official SenseVoiceSmall weights is permitted when the model license is followed; Section 3 is a responsibility and risk disclaimer rather than an additional non-commercial restriction; and fine-tuned derivative weights may remain private."
- url: https://github.com/QwenAudio/SenseVoice
- source_type: primary
- published: 2026 (issue #334 clarification cited in README)
- confidence: high

### [12] Kokoro-82M remains the lowest-risk Apple Silicon TTS: Apache-2.0 weights, 82M params, Chinese via misaki[zh] + lang_code 'z', and mlx-community ships 8/6/4-bit. PyTorch MPS path needs PYTORCH_ENABLE_MPS_FALLBACK=1; MLX path is preferred.
- quote: "With Apache-licensed weights, Kokoro can be deployed anywhere from production environments to personal projects… On Mac M1/M2/M3/M4 devices, you can explicitly specify the environment variable PYTORCH_ENABLE_MPS_FALLBACK=1"
- url: https://github.com/hexgrad/kokoro
- source_type: primary
- published: 2026 (README as fetched)
- confidence: high

### [13] Silero VAD is MIT, ~2MB, <1ms/30ms-chunk on 1 CPU thread, 8/16kHz, and has an official mlx-community/silero-vad weight — the cheapest, safest component in the VoxLab stack.
- quote: "One audio chunk (30+ ms) takes less than 1ms to be processed on a single CPU thread… JIT model is around two megabytes in size… Published under permissive license (MIT)"
- url: https://github.com/snakers4/silero-vad
- source_type: primary
- published: 2026 (README as fetched)
- confidence: high

### [14] mlx-audio ships alternative STT worth watching for VoxLab: VibeVoice-ASR (long-form up to 60min, diarization, hotwords, streaming), Parakeet v3 (25 EU langs), Nemotron 3.5 streaming, and Qwen3-ForcedAligner — meaning Whisper/SenseVoice are no longer the only MLX options.
- quote: "Microsoft's 9B parameter speech-to-text model with speaker diarization and timestamps. Supports long-form audio (up to 60 minutes) and outputs structured JSON."
- url: https://github.com/lucasnewman/mlx-audio
- source_type: primary
- published: 2026-09
- confidence: medium
